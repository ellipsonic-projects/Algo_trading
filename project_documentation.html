Algorithmic Options Trading Platform

System Overview & Technical Documentation

1. System Architecture (How the Project Works)

This project is built as a highly responsive 3-tier microservice architecture. Instead of having a single monolithic program, the system is separated into three specialized layers that communicate in real-time:

Frontend

React Dashboard

Built with Vite, Tailwind CSS, & TypeScript. It displays performance metrics, live chart trends, option chains, and controls strategies.

Backend Database API

Node.js Express Server

Connected to MongoDB. It securely handles user authentication, dashboard stats, and persistent strategy logs (trade history).

Broker Wrapper

Python FastAPI App

Directly connects to Angel One SmartAPI. It handles the secure login handshake, downloads options masters, and executes orders.

The Communication Cycle:

  • When you open the page, the React Dashboard queries the Node.js Backend to fetch historical statistics (such as Win Rate, Total Trades, and past PnL logs).
  • When you click "Connect to Angel One" and enter your MPIN, the React Dashboard sends a login trigger to the Python Service. The Python Service computes your TOTP, submits it to Angel One, and establishes a secure session.
  • Once authenticated, the React Dashboard queries the Python Service directly for live price updates (LTP), historical option charts (candles), and margins.

2. Data Sources (Where & How Data is Fetched)

The system fetches data dynamically from three external sources:

1. Angel One SmartAPI Connection (Real-time Market Ticks)
All market data (like LTP spot prices and options premiums) is fetched directly from Angel One’s official API endpoints. Every time a strategy is active, the React app sends requests to the Python microservice, which utilizes the official SmartApi python package to get raw market ticks.

2. Angel Broking CDN (OpenAPIScripMaster.json)
To fetch options contracts (such as NIFTY 24200 CE), the Python service downloads a massive JSON file on startup: OpenAPIScripMaster.json. This master list contains all active strike prices, symbols, and token keys for current and future expiries. The service parses this list to calculate the exact option symbol to buy/sell based on index spot prices.

3. MongoDB Atlas Cluster (Persistent Application Logs)
Strategy status, historical trade signals, user balances, and system logs are stored inside your MongoDB Atlas cluster. When a strategy executes a simulated or live trade, it logs the transaction to the database, updating your total PnL statistics permanently.

3. Algorithmic Strategies Detailed

The dashboard has three main strategies implemented. They analyze price candles (OHLC) in real time to generate entry and exit signals:

A. Standard Heiken Ashi Strategy

This strategy converts normal market candles into smoothed Heiken Ashi (HA) candles. Heiken Ashi filters out market noise and makes trends easier to spot. The strategy overlays a fast-moving Jurik Moving Average (JMA) and a slow-moving Exponential Moving Average (EMA) to trigger trades.

Entry Rules (Buy CE / Bullish):
  • No Lower Wick: Two consecutive Heiken Ashi candles must have no lower wick (i.e. Heiken Ashi Open = Heiken Ashi Low), representing a strong uptrend.
  • Trend Cross: The fast JMA (7 periods) must be higher than the slow EMA (20 periods).
  • Breakout Confirm: The closing price of the second Heiken Ashi candle must be higher than the JMA 7 line.
Exit Rules (Sell CE):
  • The trend weakens and two consecutive **Red** Heiken Ashi candles close (i.e. Closing price is less than the Opening price).

B. Modified Heiken Ashi Strategy

This strategy works similarly to the standard Heiken Ashi strategy, but it uses custom smoothing techniques or parameters to reduce lagging. It is designed to exit trades faster during sudden market reversals, protecting capital from fast options decay.

C. 5-Minute Premium Range Breakout

This is a momentum strategy. It focuses on the high/low range of options premium prices during the opening minutes of the trading session:

Calculation Rules:
  • Identify the Mother Candle: The strategy identifies the first candle in a lookback window (usually 4 or 5 candles) as the "Mother Candle" and measures its High and Low price.
  • Verify Inside Bars: It ensures that all subsequent candles in that window trade completely *inside* the Mother Candle's High and Low range. This represents a period of market consolidation.
Entry & Execution:
  • Breakout Entry: If a subsequent candle closes *above* the Mother Candle's High, it triggers a Buy entry immediately.
  • Target & Stop Loss:
    • Stop Loss: Set at Range Low - 2 points.
    • Target: Uses a 1:1 risk-to-reward ratio. The target points are calculated based on the distance between the entry price and your stop loss.

4. Troubleshooting & Maintenance

  • Dynamic IP Address Changes: If you lose live market data, verify if your public IP changed by visiting the SmartAPI console and updating your app's **Primary Static IP** with your current public IP address.
  • TOTP Desync: If login fails, check if the system clock on your computer is synced. If your system clock is off by even a few seconds, the generated TOTP will be incorrect, and Angel One will reject the login.
